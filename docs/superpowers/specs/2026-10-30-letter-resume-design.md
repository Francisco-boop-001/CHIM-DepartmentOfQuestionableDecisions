## Necessary restart discovery amendment (owner reviewed)
The native update requires a game restart; unresolved request IDs exist only in UI memory. Therefore add correspondence.pending.read, exact empty payload, compose access + correspondence capability, same current-context/source/owner read-only fence. Response exactly {operations:[{operationId:original request UUID,recipientLabel:string,state:stored|queued|dispatched|unknown|partial,hasTransfer:bool,canResume:bool,queuedReason:fixed|null,operatorClosed:bool}],limited:bool}; max25. No body/author/private contents. Include all unresolved manual player-paid states, including unconfirmed closed/unknown/partial/dispatched; they must not disappear after restart. Bounded candidate scan/overfetch must set limited honestly if older candidates remain. No general pagination framework.

Explicit Refresh waiting letters reads and selects the existing letter. No automatic dispatch on initialization/discovery/status. Current-scope authoritative discovery must complete before new transfer-bearing Send; unavailable/legacy unsupported/truncated results block new transfers and retain existing unresolved operations. Positive empty current-scope result may release discovery block. Do not truncate discovered records to the old three-new-operation cap. Per-letter hasTransfer persists duplicate-payment protection even without a retained draft. Unknown/partial/dispatched/closed rows stay visible but cannot Resume. Resume rechecks orphan operations (ANY operation row references document) under the writer fence, not merely doc.operation_id null. EXISTS result bounded, scan is not claimed indexed; no owner schema change.

Test additions: fresh/restarted UI discovers original request then explicit resume; unknown/partial retention and no transfer duplicate, failed/limited discovery, empty current-context positive, exact empty native/server payload and read/write classification. Old clients ignore optional metadata; new clients refuse recovery/new transfers on missing discovery support.

## Owner-approved finite-history pagination correction (supersedes fixed empty-only discovery)
A fixed first-N all-history scan can block new transfers forever after many resolved letters. The accepted correction is pending.read payload {} or exactly {cursor:nonempty opaque string<=512}, response exactly {operations:up to25,limited:boolean,nextCursor:null|nonempty string<=512}. Each request reads 25 candidate documents with one overfetch, not 500 candidates. Empty resolved pages with nextCursor are valid. limited iff nextCursor is non-null; inability to establish safe completion is an error, never a false complete result.

Use keyset(created_at,document_id) descending with initial upper watermark and last-scanned tuple, and reject a changed uppermost manual-document tuple on continuation/completion so new letters cannot be ignored. Cursor MAC uses a compact authority hash binding principal/view/serverContext/profile/scope, exact source and owner restore epoch/generation, plus expiry900s. The server-only 32-byte random key is added only during the already-existing authenticated bootstrap context-state write, never returned to the UI or generated on reads; no secret file, auth-token reuse, migration, sixth bootstrap field or owner changes. Pass the existing private key internally during current-context validation without recursively acquiring its state lock. Missing key requires automatic rebootstrap/reopen. MAC tamper/expiry/scope/context/restore tests mandatory.

UI Refresh starts a new scan but retains known unresolved operations. Explicit Continue checking waiting letters reads one page, merges all unresolved rows without three/25-row list truncation, and never auto-dispatches or loops in the background. New transfer Send remains blocked until verified end; failed/stale/incomplete scans retain known operations and cannot unlock. Selected eligible same-letter Resume remains available while pages remain. Add >26 fully resolved documents reaching a finite complete scan and an older queued/unknown 500-gold transfer beyond the first page. This correction requires an actual final native rebuild; preserve the prior native DLL/receipts as a prototype, not release evidence.


Final review amendment: the continuation cursor also signs the scoped manual player-paid document count, read under the same owner fence as the maximum tuple. A changed count returns stale_revision before scanning the next page. SF30 created_at defaults to transaction-start now(), so a late-committed earlier transaction can otherwise insert inside an already scanned keyset interval without changing its maximum. Normal owner writes do not delete manual documents; restore remains independently bound to its epoch/generation. The public cursor remains opaque and at most512bytes.
