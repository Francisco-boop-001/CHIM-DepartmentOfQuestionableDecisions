The exact dev.18 owner has a source-confirmed overlapping-initialization defect: a completed older init can erase a newer pending marker. This companion cannot reconstruct that intent. Serialize restore/init in disposable TEST; overlapping initialization is not certified. See [the dependency and restore limits](DEV18-COMPATIBILITY.md).

Read-only detail/reconcile calls for absent IDs legitimately return not_found and roll back their snapshot. The positive signed-unknown proof above uses actual composed operations and owner-accepted receipts. The unrelated-event case appends its event while the initial restore-state query is blocked, before the ingress token is returned; it does not prove an event arriving after capture. A restore epoch race after beginCommit may retain pendingCommit/unknown_locked state, which is uncertainty rather than a known no-op. The beginCommit timing case observes the journal marker before blocked owner DDL, not before every request SQL statement. The closed-connection case exercises the real owned-close helper, separately from the injected read-fence unlock failure.

Later failed preflights and TEST runs are preserved separately. Run 9's nested transaction failure led to the read-store mapping fix; the green run above supersedes its acceptance result, not its evidence.
