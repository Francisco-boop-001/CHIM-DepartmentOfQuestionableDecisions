## Transaction memo and migration boundary

`CorrespondenceStore::transactionMemo(string $key, callable $build): mixed` memoizes a value only while the store is in an active transaction. Calls outside a transaction evaluate the callback without retaining the result. The existing transaction cleanup clears the memo, so this is request/transaction-local read work; it adds no persistent memo table, replay record, receipt, or new replay authority. Protocol and wire fields remain unchanged.

Migration `006_history_indexes.sql` conditionally adds the partial expression index `correspondence_written_evidence_document_id_idx` on `public.eventlog` for `type='info'` and `sess='written_evidence_v1'`. It accelerates written-source replay lookups but changes no stored replay data. Creating the index requires the database role to own `public.eventlog` or belong to its owning role. `ensureSchema()` runs the migration only when the index is absent inside the owner's `writerTransaction`, which sets `lock_timeout='3s'`, takes the existing advisory transaction lock, and holds `SHARE ROW EXCLUSIVE` on `public.eventlog` through commit. `lock_timeout='3s'` limits lock-acquisition waits only; an ordinary `CREATE INDEX` can hold that table lock and block eventlog writers for the full index build on large histories. The frozen `writerTransaction` sets no `statement_timeout`, so no three-second index-build bound may be claimed. Failure to create or verify the index fails closed. This is an owner-source operational risk, not a measured delay or runtime failure. The owner accepts this as a one-time upgrade requirement: stop game/workers that write history for the maintenance window, or have the eventlog owner pre-create the index before resuming them.

These are source and package pairing boundaries. They do not certify a current Linux/CHIM server, database migration against a live database, HTTP/provider behavior, installed game, or Skyrim runtime. The 12 Windows MMP journal fixture failures remain the same prealpha.23 baseline failures and are not counted as passing evidence for this candidate. Candidate build and release status are not asserted here.
